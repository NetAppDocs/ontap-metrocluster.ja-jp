= MetroCluster IP WAN ISL輻輳制御を設定する
:allow-uri-read: 


[role="lead"]
ONTAP 9.20.1以降では、MetroCluster IP構成でWAN Inter-Switch Link（ISL）輻輳制御を有効にすることで、10Gbps、25Gbps、40Gbpsなどの低帯域幅または混在する帯域幅で動作するISLを、100GbpsのMetroCluster IPバックエンドポート速度を持つプラットフォームで使用できるようになります。

100Gbpsアダプタが生成するレプリケーショントラフィックは、リンク速度の低いISLをオーバーランする可能性があり、スイッチバッファの負荷増大、PAUSEバックプレッシャー、パケット損失、およびレプリケーションの不安定化を引き起こすおそれがあります。WAN ISL輻輳制御は、ISL帯域幅とノード数を使用して送信スループットの上限を計算することで、この問題に対処します。この上限は、相互接続転送トラフィックを制御する送信スループットのしきい値として機能します。測定された送信スループットが計算された上限を超えた場合、転送は拒否され、相互接続ネットワーク上で送信スループットのしきい値が適用されます。


CAUTION: WAN ISLの輻輳制御を設定しても、低帯域幅のISLを使用した場合に発生する可能性のあるパフォーマンス上の問題が発生しないことを保証するものではありません。NetAppは、最適なパフォーマンスを得るために、100Gbps ISL接続への移行を強くお勧めします。

.このタスクについて
* MetroCluster IP構成は、ONTAP 9.20.1以降を実行している必要があります。
* WAN ISLの輻輳制御はデフォルトでは無効になっているため、明示的に有効にする必要があります。
* 以下のシナリオでこの機能を設定するには、NetAppサポートに連絡する必要があります：
+
** 機能の有効化または更新時にISL情報が自動的に取得できない場合
** 同じスイッチに接続された2つの4ノードMetroCluster IP構成がある場合
** 機能を有効にした後に計算された上限値を変更する必要がある場合


* 輻輳制御を有効にした後にトポロジーが変更された場合は、新しい上限値を計算するために輻輳制御の設定を更新する必要があります。たとえば、ISLの数や速度が変更された場合や、MetroCluster IP構成に新しいノードを追加した場合などです。
* 各サイトは独自に上限を算出します。ローカルサイトで `metrocluster interconnect congestion-control enable`コマンドを実行すると、次の処理がトリガーされます：
+
** ローカルサイトは、その上限を準備して計算します。
** パートナーサイトは、コマンドが実行されるローカルサイトとは別に、上限値を準備および計算します。技術的には可能性は低いものの、ローカルサイトとパートナーサイトでは異なる上限値が算出される可能性があります。これは想定される動作であり、故障や設定ミスを示すものではありません。
** 各サイトは計算した値を目的の状態として書き込み、カーネルがそれを適用します。


* WAN ISL輻輳制御は、有効化されると自動的に動作します。




[[enable-congestion-control]]
== 輻輳制御を有効にする

WAN ISL輻輳制御を有効にするには、ローカルクラスタで以下の手順を実行してください。


CAUTION: 同じスイッチに接続されている2つの4ノードMetroCluster IP構成がある場合は、この機能を有効にするためにNetAppサポートにお問い合わせください。

.手順
. cluster_AでWAN ISL輻輳制御を有効にする：
+
[source, cli]
----
metrocluster interconnect congestion-control enable
----
+
コマンドが `MCC_CC_ISL_INFO_UNAVAILABLE`エラーで失敗した場合、ISL情報は自動的に取得できないため、この機能を有効にするにはNetAppサポートにお問い合わせください。

. WAN ISL輻輳制御が有効になっていることを確認してください：
+
[source, cli]
----
metrocluster interconnect congestion-control show
----
+
[listing]
----
cluster_A::> metrocluster interconnect congestion-control show

Node            Enabled Ceiling (MiB/s)
--------------- ------- ---------------
cluster_A-01    true    1250
cluster_A-02    true    1250
2 entries were displayed.
----



NOTE: この機能を有効にした後に計算された上限値を変更する必要がある場合は、NetAppサポートにお問い合わせください。



[[refresh-congestion-control]]
== 輻輳制御の更新

WAN ISLの輻輳制御設定を更新するには、ローカルクラスタで以下の手順を実行してください。ISLの数や速度が変更された場合や、新しいノードがMetroCluster IP構成に追加された場合など、トポロジが変更されたときは常に輻輳制御構成を更新する必要があります。

.手順
. cluster_A の WAN ISL 輻輳制御設定を更新します：
+
[source, cli]
----
metrocluster interconnect congestion-control refresh
----
+
ONTAPは現在のネットワーク状況に基づいて新しい上限値を計算し、自動的に適用します。

+
コマンドが `MCC_CC_ISL_INFO_UNAVAILABLE`エラーで失敗した場合、ISL情報は自動的に取得できないため、設定を更新するにはNetAppサポートにお問い合わせください。





[[monitor-wan-isl-congestion-control-activity]]
== WAN ISL輻輳制御アクティビティを監視する

以下のコマンドを使用して、輻輳制御が期待どおりに機能していることを確認できます：

[source, cli]
----
metrocluster interconnect congestion-control show
----
有効にした場合、出力は次の例のようになります：

[listing]
----
cluster_A::> metrocluster interconnect congestion-control show

Node            Enabled Ceiling (MiB/s)
--------------- ------- ---------------
cluster_A-01    true    1250
cluster_A-02    true    1250
2 entries were displayed.
----
また、 `-instance`パラメータを使用して、各ノードのより詳細な情報を表示することもできます：

[source, cli]
----
metrocluster interconnect congestion-control show -instance
----
[listing]
----
cluster_A::> metrocluster interconnect congestion-control show -instance

                        Node Name: cluster_A-01
       Congestion Control Enabled: true
       Throughput Ceiling (MiB/s): 1250

                        Node Name: cluster_A-02
       Congestion Control Enabled: true
       Throughput Ceiling (MiB/s): 1250
2 entries were displayed.
----


[[disable-congestion-control]]
== 輻輳制御を無効にする

.手順
. cluster_A で WAN ISL 輻輳制御を無効にします：
+
[source, cli]
----
metrocluster interconnect congestion-control disable
----
. 機能が無効になっていることを確認してください：
+
[source, cli]
----
metrocluster interconnect congestion-control show
----
+
出力は以下の例のようになるはずです。

+
[listing]
----
cluster_A::> metrocluster interconnect congestion-control show

Node            Enabled Ceiling (MiB/s)
--------------- ------- ---------------
cluster_A-01    false   -
cluster_A-02    false   -
2 entries were displayed.
----
